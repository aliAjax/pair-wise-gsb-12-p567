# 车辆调度与接力派车

- 行业：物流
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 业务规则冒烟测试：`npm run test:smoke`（29 个断言，覆盖派车/4小时/检修/并发/恢复）

数据保存在浏览器 localStorage，每次保存都写入一份完整快照，重开页面可继续；保存失败时自动从最近完整记录恢复。

## 解决的调度问题

过去一名司机一辆车跑完整任务，车辆检修或司机连续在途超时后只能口头叫接班，任务状态与车辆占用对不上。本工具把车辆、司机、任务、接力单串成一条链：

### 1. 任务按站点拆段，段即接力单
- 新建任务时填写有序站点，相邻两站自动拆为一个段（N 站 N-1 段）。
- 每个段独立绑定 **车辆 + 司机 + 起止时段**，状态流转：
  `待接力 → 已派车 → 在途 → 已到站`；派车被撤回时进入 `退回待接力`。

### 2. 四小时连续在途强制接力
- 同一司机相邻两段间隔不足 30 分钟视为未休息、连续在途（`src/rules.ts` 的 `driverChains`）。
- 任一段派车后该司机连续在途将超过 4 小时，派车直接被拒，需换接力司机；
  间隔 ≥30 分钟则连续时间重新起算。
- 司机面板有连续在途进度条，到达 4 小时变红。

### 3. 检修车辆不能排入
- 车辆标记检修时必须填写原因，派车下拉中不可选、校验直接拒绝。
- 标记检修瞬间：该车辆**未出发**的已派段自动退回待接力区并写明原因；
  **在途段保留原绑定**，记录"到站登记后再交接"。

### 4. 资源不可用时的处理
- 车辆检修、司机请假/超时不可用：未出发段退回待接力区（解绑车/人/时段，原因写在段卡片和交接记录上）；
  已出发段一律保留原绑定，只有到站登记之后才能改派交接。

### 5. 两人同时派车：先到先得
- 打开派车面板时记录该段当前派车批次（ticket），提交瞬间二次校验；
- 后提交的一方若发现段已被他人先派成功，直接拒绝并提示"先到的一方保留"。
- 全局提交锁防止同一客户端并发写入。

### 6. 保存失败 → 从最近完整记录恢复
- 每次提交采用"先内存应用、再完整保存、失败即回滚"：
  `saveAll` 同时写当前记录与快照历史，任何一步抛错都恢复到最近一次完整快照（`src/storage.ts`）。
- 页面顶部"模拟一次保存失败"按钮可演示：下一次派车/登记失败后自动回滚，数据不丢。

### 7. 页面与持久化
- 按任务展示站点链路、各段状态、车/人/时段绑定与交接动作；
- 右侧待接力区（含退回原因）、车辆占用面板（每辆车各时段占用）、
  司机连续在途面板；底部交接记录时间线可按任务筛选。
- localStorage 保存完整状态，重开浏览器后继续；"重置数据"可恢复演示数据。

## 目录结构

```
src/
  types.ts        领域模型：车辆/司机/任务/段/交接记录/快照
  rules.ts        纯规则：时段重叠、连续在途链、4 小时判定
  storage.ts      完整快照持久化 + 保存失败模拟 + 恢复
  seed.ts         演示数据（含在途、已派、退回等各种状态）
  store.ts        Pinia store：派车/出发/到站/退回/检修/并发/事务
  components/     TaskBoard / PendingPool / VehiclesPanel /
                  DriversPanel / HandoverLog / DispatchDialog /
                  CreateTaskDialog
scripts/smoke.mjs 业务规则冒烟测试（esbuild 打包后在 Node 跑）
```
