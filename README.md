# 车辆调度接力台

- 行业：物流
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

把车辆、司机、任务和接力单接上，替代"一名司机一辆车跑到底、不行了口头叫接班"的方式。

## 业务规则

- **任务按站点拆段**：创建任务时按站点顺序填写（如 `集配仓 → 城北站 → 大学城站`），相邻两站自动拆为一段。
- **每段绑定车辆、司机和起止时段**：派车/改派时选择车辆、司机并填写计划起止时间。
- **司机连续在途上限 4 小时**：连续在途达到 4 小时的司机不能再接下段；到站登记时累计在途时长，超限自动进入休息，其未出发段自动退回待接力区。休息复位后连续在途清零。
- **检修车辆不能重新排入**：派车和出发时都会校验。
- **车辆或司机不可用时**：
  - 未出发的段退回待接力区，并写清原因（哪辆车检修 / 哪位司机超时）；
  - 已出发的段保留原绑定，标记"到站后交接"，等到站登记时生成交接记录。
- **待接力区**：集中展示退回的段和原因，可直接改派新车辆/司机，自动生成接力单。
- **页面按任务显示**各段状态、车辆占用和交接记录。

## 并发与持久化

- 数据保存在 localStorage（键 `dfwlfront-3-dispatch`），每次提交整体写入一条带版本号的完整记录，重开页面可继续。
- 两人同时提交派车（可开两个浏览器标签页验证）：以版本号做乐观并发控制，先到的一方保留；后提交的一方保存失败，自动从最近完整记录恢复，并收到提示。
- 另一标签页提交后，本页会通过 storage 事件自动同步最新记录。
